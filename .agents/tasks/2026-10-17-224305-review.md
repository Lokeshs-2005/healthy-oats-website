# Product Features Enhancement — Pricing Tiers, Image Gallery, and Dual Admin Emails

This change adds product pricing tiers (quantity-based pricing), additional image galleries, and dual-admin email notification. The admin can now define multiple size/quantity options per product (e.g., 250g at ₹99, 500g at ₹180), upload up to 5 additional product images shown as a thumbnail gallery, and send order notifications to two admin email addresses. The customer-facing flows adapt to show "from ₹X" pricing on tiered products, a size selector on the product detail page, and proper tier information in the cart and checkout.

**Watch for:** Email configuration silently falls back on misconfiguration (confirmed), tier price lookup re-fetches from product instead of trusting cart price (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The product schema adds two optional fields: `additionalImages` (up to 5 URLs) and `pricingTiers` (up to 10 quantity/price pairs). ProductFormModal provides dynamic add/remove controls for both. Backend validates and stores them; products without these fields continue using `basePrice` and single `imageUrl`.

MenuPage shows "from ₹X" for tiered products (minimum tier price). ProductDetailPage renders a size selector that updates the displayed price and passes the selected tier to cart. CartContext generates composite IDs (`productId:quantity`) so different sizes of the same product appear as separate cart rows. Cart items store `selectedQuantity` and `selectedPrice`.

Order service reads `item.selectedQuantity`, looks it up in the product's `pricingTiers`, and uses the matched tier price. If no match or no tiers, falls back to `item.selectedPrice` or `basePrice`. This re-lookup is fragile: if an admin changes a tier's quantity label after items are in carts, the lookup fails and pricing breaks.

ProductDetailPage displays additional images as clickable thumbnails. Clicking swaps the image into the main view. Email service reads `ADMIN_EMAILS`, splits on comma, and sends admin notifications to all listed addresses. Silent fallback to single email if misconfigured.

## Order service tier price lookup is redundant

`orderService.js` lines 129-137 match `item.selectedQuantity` against `product.pricingTiers` to re-fetch the tier price. If a match is found, `selectedPrice` is set to the matched tier's price. Otherwise, it falls back to `item.selectedPrice` or `unitPrice`.

The cart already stores `selectedPrice` at add-to-cart time. If the admin changes a product's pricing tiers after items are in carts, the backend will either use the old cart price (if the quantity label changed) or the new product price (if the label still matches). Prices should lock at cart-add time. Trust `item.selectedPrice` directly and skip the product fetch.

## Email service dual-admin fallback is silent

`emailService.js` lines 150-159 read `ADMIN_EMAILS`, split on comma, trim, and filter empty strings. If the array is empty, line 159 falls back to `settings.businessEmail || fromEmail`.

If `ADMIN_EMAILS` is misconfigured (e.g., `"  ,  ,"` or undefined), the split/trim/filter produces an empty array, the fallback runs silently, and only one recipient gets the email instead of two. No warning is logged.

## Pricing tiers allow duplicate quantity labels

`productService.js` lines 49-67 validate `pricingTiers` but don't check for duplicate `quantity` values. If the admin submits two tiers with "500g", both are stored, and the order service matches the first one.

## Additional images lack upload button

ProductFormModal line 172 provides an upload button for the main image, but additional images (lines 186-217) require manual URL entry. The admin can upload via the main field and copy the URL, but this is inconsistent.
