# Product Features Enhancement — Pricing Tiers, Image Gallery, and Dual Admin Emails

This change implements three customer-requested features: pricing tiers for quantity-based pricing (e.g., 250g at ₹99, 500g at ₹180), additional product image galleries (up to 5 images), and dual-admin email notifications. The changes touch the product schema, admin interface, customer-facing pages, cart logic, and order processing. The implementation correctly removes the broken category/addon references from AdminDashboard, wires the new features end-to-end from product creation through cart to order placement, and fixes the two blocking issues identified in the prior review pass: tier price lookup fragility and silent email fallback.

**Watch for:** Nothing blocking. The prior review's two confirmed issues (tier price re-lookup and silent email fallback) have been fixed in commit 11c6581.

**Verdict**: APPROVED

## High-level view

The product schema gains two optional arrays: `additionalImages` (capped at 5 URLs) and `pricingTiers` (capped at 10 quantity/price pairs). Products without these fields continue working with `basePrice` and single `imageUrl`. ProductFormModal provides dynamic add/remove controls for both fields with clear UI limits. Backend validation enforces length caps, type checks, and non-negative prices.

MenuPage displays "from ₹X" for tiered products (showing the minimum tier price). ProductDetailPage shows a size selector dropdown when tiers exist, updates the displayed price on selection, and passes the selected tier to cart. CartContext generates composite item IDs (`productId:quantity`) so different sizes of the same product appear as separate cart rows, and stores both `selectedQuantity` and `selectedPrice` at add-to-cart time.

Order service trusts the `selectedPrice` from the cart item directly, preventing pricing errors when admins change tier labels after items are in carts. Email service reads `ADMIN_EMAILS` from environment, splits on comma, and sends admin notifications to all listed addresses. If misconfigured, logs a warning and falls back to single admin email.

ProductDetailPage renders additional images as clickable thumbnails below the main image. Clicking a thumbnail swaps it into the main display.

## AdminDashboard getCategories error is fixed

Commit 43c2dac removed category and addon features from the codebase. AdminDashboard no longer calls `getCategories()` or `getAddOns()`. Grep search confirms no remaining references to these functions in any `.jsx` file.

## Order service trusts cart prices directly

The latest commit (11c6581) removed the tier price re-lookup logic flagged in the prior review. `orderService.js` now trusts `item.selectedPrice` directly (lines 184-188). This prevents pricing errors when admins rename tier quantity labels after customers have added items to cart.

## Email service warns on misconfiguration

`emailService.js` (lines 151-153) logs a console warning when `ADMIN_EMAILS` is undefined, empty, or contains only whitespace/commas. The warning message explicitly states "ADMIN_EMAILS environment variable is not configured or empty. Falling back to single admin email."

## Product validation doesn't prevent duplicate tier labels

`productService.js` doesn't check for duplicate tier quantity labels. An admin could create two tiers with "500g". Since price is locked at add-to-cart time, this doesn't cause pricing errors, but creates a confusing admin experience when setting up products.
